# PHP 门户系统（前台搜索 + 导航分组 + 登录 + 分用户组/单用户授权 + 后台管理）
- ## 纯AI零添加
一套基于 **PHP + MySQL** 的门户系统，密码使用 **MD5** 保存，无注册功能，用户账号由管理员在后台单个新增或批量导入。

## 功能

- **前台首页**：居中搜索栏，支持必应 / 百度 / Google 切换，回车即在新标签页打开搜索结果。
- **导航按分组展示**：导航项归属于导航分组，首页按分组（分类）分区展示导航卡片，不再堆在单一列表里。
- **登录**：账号密码登录（密码 MD5 保存）。无注册入口，账号由管理员统一开通。
- **双维度授权**：既能按「用户组」整体授权，也能对「单独某个用户」授权可见性；授权粒度可到**导航分组**或**单个导航项**：
  - 一个导航分组：设置对哪些用户组可见 + 对哪些单独用户可见；
  - 一个导航项：同样可设置对哪些用户组可见 + 对哪些单独用户可见；
  - 分组/项均不设授权 = 对所有人公开；分组只有在其下存在至少一个可见导航项时才显示。
- **后台管理（仅管理员组可见）**：
  - **页面格局**：统一采用「左侧菜单 + 右侧内容」的标准后台布局——侧边栏吸顶跟随滚动、激活项带主色指示条；内容区为「页头（标题+副标题）→ 规则说明 → 工具/表单卡片 → 数据表格 → 分页」的标准层次；规则说明默认折叠，列表页聚焦数据。全部样式使用 `:root` CSS 变量（主色、中性色、圆角、投影），换肤只需改变量。
  - **弹窗化操作**：导航分组、导航项、用户组三页的「新增 / 批量添加 / 编辑」均通过统一弹窗完成，表单在弹窗内按「📋 基础信息 → 👀 谁可以看到 → 🛠️ 谁可以管理」分区展示；勾选清单为固定高度、可搜索的紧凑面板（范围外授权灰色冻结），列表中只保留摘要标签（🌐 公开 / 限 N 组·N 人 / 🛠️ N 组可管理）。提交出错时弹窗自动重开并保留填写内容。
  - 导航分组管理：新增 / 编辑 / 删除分组，配置图标、排序、启用状态、可见用户组、可见单独用户；列表分页显示（每页 10/20/50/100 条可选）；支持**批量添加**（文本域每行一个分组名，可统一设置可见范围）。
  - 导航项管理：选择所属分组，配置标题、URL、图标、排序、启用状态、可见用户组、可见单独用户；可按分组筛选，列表分页显示（翻页保留筛选条件，每页条数可选）；支持**批量添加**（每行「标题 | URL | 图标（可选）」，归属同一分组）。
  - **导航点击管理**：后台概览「导航点击」页签，独立权限 `manage_nav_clicks`——支持按标题/URL 与分组筛选、每页 10/20/50/100 条分页、单个清零与勾选批量清零；该权限可由系统管理员组在矩阵授予管理员组，也可二级授权。
  - **本站探针**：后台概览页以紧凑卡片网格展示 PHP/MySQL 版本、服务器与系统信息、执行时间/内存/上传限制、磁盘空间、负载与运行时间等运行环境数据（仅管理员可见，可折叠）。
  - 两页面的普通管理员均**仅可查看、修改、添加、删除其可管理用户组有权访问的内容**（公开内容除外）：导航项只能归属可管理的导航分组，可见性可授予可管理的用户组 / 用户以及本人所属用户组；范围外的现有归属与授权以灰色冻结保留、不会被改动。系统管理员不受限制。两个权限均可在权限矩阵分配，也可经二级授权授予。
  - **导航分组可管理用户组**：系统管理员可在「导航分组管理」中为每个分组勾选「可管理用户组」（存于 `nav_groups.manageable_group_ids`）；命中用户组的成员无需系统管理员身份，即可对该分组及其下全部导航项增删改查。该设置超管可直接改；**持有 `can_delegate`（允许二级授权）的普通管理员同样可设置，但只能指定本人可管理的更低级别用户组**，范围外现有值冻结保留。结合二级授权授予的 `manage_navgroups` / `manage_nav` 页面权限，可实现「能进后台 + 只管指定分组」的分权管理。
  - 普通管理员配置导航分组 / 导航项可见性时，可见用户组候选包含其**本人所属组**（标注「本组」），避免把可见性授予可管理组后自己反而在前台看不到所管理的内容。
  - 权限管理页采用与用户管理一致的**页签布局**：「权限矩阵」「用户级授权」两个页签切换（非超管默认进入授权页签）。
  - 用户组管理：新增 / 编辑 / 删除用户组；超级管理员可直接设置组类型（普通组 / 管理员组 / 超级管理员组）。
  - 用户管理：单个新增、批量导入（文本 / CSV）、搜索、**按用户组筛选（含「无分组」，管理员/普通用户两个页签均可）**、改显示名、调分组、删除；**新建用户为独立权限 `create_users`**（默认随用户管理授予，可单独撤销）；**同一用户可同时属于多个用户组**（勾选保存，级别与权限取各组并集）；并可为每个单独用户勾选其可见的导航分组与导航项。
  - **用户主题管理**：独立权限 `manage_user_themes`（默认授予现存管理员组，可单独撤销）——持权管理员可在用户管理两个页签中查看每个用户当前使用的皮肤（操作列按钮直接显示皮肤名），展开后可**增/改**（从站点可见皮肤中选择）或**删**（清除个人选择、跟随站点默认）；目标仍受级别与可管理范围限制（只能管理更低级别用户或自管组同组成员）；该权限可在权限矩阵授予管理员组，也可二级授权。
  - **主题皮肤系统**：内置经典蓝、梦幻紫、翡翠绿、玫瑰红、琥珀橙、青碧、暗夜 7 套皮肤；用户可在 `/theme.html` 公开切换页选择皮肤（登录用户按账号记忆，访客写 cookie），顶栏「🎨 主题」入口可在站点设置中开关。系统管理员组可在后台「主题皮肤管理」设置每套皮肤的**对用户可见性与站点默认皮肤**（权限 `manage_themes`）——只有可见皮肤才会出现在切换页；还可**按用户组限定可见范围**（不勾选=所有用户及游客可见，勾选后仅勾选组成员可见）。
  - **皮肤元数据管理**：独立权限 `manage_theme_meta`——持权管理员可在后台直接修改每套皮肤的**名称、版本、作者、说明、暗色类型（跟随原始/强制暗色/强制浅色）、可见用户组**，覆盖值存入 `theme_overrides` 表、不修改 CSS 文件；支持一键清除覆盖恢复原始值；该权限可在权限矩阵授予管理员组，也可二级授权。皮肤开发规范见 [主题皮肤开发文档](docs/主题皮肤开发文档.md)：向 `assets/themes/` 放入带规范注释头的 CSS 文件即可扩展新皮肤。
  - 关于我们设置：编辑关于我们页面的简介标语、详细介绍与功能特性卡片；默认仅系统管理员，可授予用户组或单个用户（二级授权）。
  - 权限管理：权限矩阵与二级授权均按四大分类分组展示——**系统基础**（后台访问、主题皮肤管理、皮肤元数据管理、允许二级授权）、**门户导航**（导航分组 / 导航项 / 用户导航 / 搜索引擎）、**用户管理**（用户组 / 用户 / 新建 / 重置密码 / 批量导入 / 用户主题管理）、**内容与记录**（网站参数 / 关于我们 / 用户日志 / 搜索记录 / 导航点击管理）。清单内**每一项权限**都可在矩阵分配，也可二级授权给单个用户（含「后台访问权限」「允许二级授权」本身，后者可逐级再授权）。

## 批量导入用户

在「用户管理」→「批量导入用户」页面，支持两种方式：

1. **粘贴文本**：每行一条，列顺序与官方模板一致 `用户名,密码[,显示名][,用户组]`，`#` / `;` 开头为注释；首行可直接粘贴表头 `用户名,密码,显示名,用户组`，会被自动识别跳过。
2. **上传 CSV**：使用官方模板「批量导入用户信息.csv」，列顺序 `用户名,密码,显示名,用户组`；表头行自动识别跳过（中英文表头均兼容），支持 UTF-8（含 BOM）与 GBK 编码；字段按标准 CSV 解析，支持带引号字段。

页面提供「⬇️ 下载 CSV 模板」按钮（`/admin/import.html?template=1`），下载的模板带 UTF-8 BOM，Excel 打开不乱码。

已存在的用户名会自动跳过，不重复导入。未填写用户组的行使用所选「默认用户组」。「用户组」列支持一次填写多个组，以 `|` 分隔，例如 `普通用户组|管理员组`。

## 环境要求

- PHP >= 7.4（建议 8.x），需启用 `pdo_mysql` 扩展。
- MySQL 5.7+ 或 MariaDB。数据库可不存在，首次运行会自动创建 `portal` 库与表结构。

## 配置数据库

编辑 `includes/db.php` 顶部连接配置：

```php
$DB_HOST = '127.0.0.1';
$DB_PORT = 3306;
$DB_NAME = 'portal';
$DB_USER = 'root';
$DB_PASS = '';
```

## 运行方式

**开发（PHP 内置服务器，支持伪静态）：**
```bash
cd portal-php
php -S localhost:8000 router.php
```
浏览器打开 <http://localhost:8000> 即可（访问 <http://localhost:8000/index.html> 也等效）。

**生产（Apache / Nginx）**：见下方「伪静态配置」。

## 伪静态配置

系统已启用伪静态地址（如 `/jump/12.html`、`/login.html`、`/admin/navs.html`），项目根目录内置多套配置，任选其一：

| 文件 | 适用环境 | 说明 |
|------|---------|------|
| `baota-nginx-伪静态规则.txt` | **宝塔面板 Nginx** | 粘贴到「网站 → 设置 → 伪静态」即可，推荐 |
| `baota-完整站点配置参考.conf` | 宝塔 Nginx | 需要整体替换/核对站点配置时参考 |
| `.htaccess` | Apache (mod_rewrite) | 放到项目根目录，开启 AllowOverride All |
| `nginx-portal.conf` | 普通 Nginx | server 块，改 root/server_name/fastcgi_pass 后使用 |
| `router.php` | PHP 内置服务器 | `php -S localhost:8000 router.php`，与上面规则一致 |

**宝塔用法（推荐）：**
1. 把站点根目录指向 `portal-php` 项目目录；
2. 宝塔 → 网站 → 站点 → 设置 → 伪静态，把 `baota-nginx-伪静态规则.txt` 里的规则整段粘贴保存；
3. PHP 处理由宝塔自带的 `include enable-php-XX.conf;` 负责，无需手动配 fastcgi。

伪静态路由表：

```

/mynav.html              ->  my_nav.php       （我的自定义导航，每用户自助）
```

## 用户权限体系

- **用户组与级别（level，数字越小级别越高）**：
  - ⭐超级管理员组 = 级别 1，自动拥有全部权限；
  - 🛡️管理员组 = 级别 2，默认拥有后台访问及导航/用户等管理权限；
  - 👥普通组 = 级别 3+（系统管理员可在用户组编辑中自定义级别）。系统管理员设置的自定义级别永久保留，不会再被迁移逻辑覆盖（旧库历史错位仅在升级时一次性校正）。
  - **组类型由超级管理员在用户组编辑中直接设置**（普通组 / 管理员组 / 超级管理员组）；管理员组自动包含 `access_admin`，普通组需要后台访问时由超管显式勾选对应权限，类型与权限保持一致。系统中始终至少保留一个超级管理员组（最后一个不可降级）。
- **多用户组**：一个用户可同时归属任意多个用户组——是否超管/管理员取「任一组命中」，级别取所属组最高（数字最小），组权限取各组**并集**。归属以 `user_group_members` 关联表为准，`users.group_id` 仅缓存其主组（级别最高组），任何归属变更后自动重算。
- **权限项**：`access_admin`（后台访问）、`manage_navgroups`（导航分组）、`manage_nav`（导航项）、`manage_groups`（用户组）、`manage_users`（用户管理）、`create_users`（新建用户）、`reset_password`（重置密码）、`import_users`（批量导入）、`manage_user_navs`（用户导航管理）、`manage_engines`（搜索引擎）、`manage_settings`（网站参数）、`manage_about`（关于我们设置）、`view_logs`（查看用户日志）、`view_search_logs`（搜索记录查看）、`can_delegate`（允许二级授权）。
- **按权限显隐**：侧边栏与页面内所有操作组件均按权限渲染——无权限的功能入口、按钮、表单（包括隐藏的编辑行）都不会出现在页面 HTML 中（如只有重置密码权限的管理员仅看到重置密码按钮，无新建/编辑/删除入口；`manage_settings`/`manage_about` 等权限持有人才能进入对应设置页）；服务端同样逐操作鉴权，直接构造请求无法越权。
- **可管理用户组（管理范围）**：不仅管理员组，**普通用户组也可分配可管理用户组**——其成员可管理被分配组内、级别更低的用户。**可把本组自身勾入范围，构成"自管组"**：组内成员可互相管理（改资料、重置密码、删除等），但不能操作自己本人，也不能改动同级组的归属（即不能把同伴移出本组、或把自己移出本组）。仅普通组可被分配为管理范围（不能管理管理员组/超管组）。
- **管理员用户组的管理**：系统管理员有权添加、修改、设置类型（可升级为超级管理员组，也可收回为普通组）与**删除用户组**；删除/降级后自动重算受影响用户的主组与身份。超级管理员组（级别 1）任何情况不可删除；删除管理员组仅限系统管理员本人操作。
- **同级隔离、相互可见**：管理员只能管理级别"低于"自己的用户；**同级管理员禁止相互增删改**（含系统管理员之间），但在「用户管理 → 管理员」页签中**可相互查看**信息，同级/更高级别行为只读。唯一例外是自管组：其同组普通成员可互相管理；但权限授予（二级授权）始终不允许同级互授。
- **后台入口**：拥有 `access_admin` 权限的用户才能进后台；具体页面另受各权限控制；无权限访问会跳回首页（直接输入 URL 同样被拦）。
- **权限即时生效**：每次请求会从数据库同步当前用户的级别与权限，系统管理员的调整无需等用户重新登录。

## 权限管理与二级授权

后台 → 🔐 权限管理（`/admin/permissions.html`），两大功能：

1. **权限矩阵**：以"权限 × 用户组"矩阵查看组级权限；系统管理员可直接勾选保存，其他管理员只读。本人持有的权限行有绿色标记。
2. **用户级授权（二级授权）**：把权限直接授予单个用户：
   - 系统管理员可授予/撤销任意权限、任意更低级别用户；
   - 被授予 **`can_delegate`（允许二级授权）** 的用户，可把**自己持有的权限**授予级别低于自己、在其管理范围内的用户；不能授予自己没有的权限，且只能撤销"本人授予"的授权（授权记录显示授权人与时间）。授权清单按权限分类以可搜索的紧凑面板展示，组权限项灰色冻结、附「组」标签。
- 用户最终权限 = 用户组权限 ＋ 用户级授权；权限变更即时同步，无需重新登录。

## 修改密码

- **用户自改**：登录后顶栏「🔒 修改密码」（`/password.html`），验证当前密码后修改，md5 保存。
- **管理员重置**：后台 → 用户管理 → 每行「🔑 重置密码」，无需原密码直接设置新密码。该操作受独立的 **`reset_password`（重置用户密码）** 权限控制：管理员用户组默认拥有，可在权限矩阵中调整，并支持经二级授权授予单个用户（无需授予完整用户管理权限）。
- **用户管理分区**：用户管理按「🛡️ 管理员」与「👥 普通用户」两个页签分区展示；管理员页签可相互查看但不可对同级/更高级别做任何修改。

## 登录设备与设备数限制

- **登录设备登记**：每次登录按服务端会话在 `user_sessions` 表登记一行：设备名（由 User-Agent 解析操作系统 + 浏览器，如「Windows · Chrome」）、IP、登录时间、最后活跃时间（每 30 秒心跳更新）；升级前已登录的老会话首次请求时自动补登。
- **最大登录设备数**：后台「网站参数设置 → 登录与会话」可设置每个账号允许同时在线的最大设备数（0 = 不限制，默认不限）。超过限制的新登录将被拒绝，需先在其他设备退出或联系管理员下线。
- **管理员强制下线**：用户管理每行新增「📱 设备」按钮，弹窗列出该用户全部登录设备及状态（当前设备 / 登录中 / 已下线），可对非当前设备「强制下线」——对方下次请求即被引导重新登录。需 `manage_users` 权限且目标用户在管理范围内；普通管理员不能操作同级/更高级别用户的设备。
- **用户自助管理**：登录用户可在「⚙️ 设置」（`/settings.html`）中查看全部登录设备，并下线自己的其他设备。
- 已吊销设备行保留 7 天供审计，之后自动清理；90 天不活跃的会话行自动删除。

## 我的设置（用户中心）

公开给所有登录用户的设置中心（`/settings.html`，顶栏「⚙️ 设置」进入），采用**左侧列表菜单 + 右侧内容面板**布局，菜单支持 hash 定位（如 `/settings.html#devices`），≤880px 时菜单变为顶部横向滚动条：

| 菜单项 | 内容 |
| --- | --- |
| 🏠 主页 | 问候语与实时时钟；基本信息（登录账号 / 显示名 / 用户组 / 注册时间 / 上次登录 IP / **最大同时在线设备数**）；自定义导航与登录设备两个速览区，设备可直接快捷下线 |
| ⭐ 我的导航 | 个人自定义导航的增删改查（仅本人可见；原 `/mynav.html` 页面继续保留） |
| 📱 登录设备 | 全部设备详情（设备 / IP / 登录时间 / 最后活跃 / 状态），可强制下线其他设备 |
| 🔒 修改密码 | 验证当前密码后修改（原 `/password.html` 页面继续保留） |
| 🎨 主题皮肤 | 切换界面配色，选择保存在账号中（受站点总开关与可见皮肤数量控制） |

### 「我的设置」入口的每用户开关

- 管理入口位于 **网站参数设置 → ⑦ 用户设置入口管理**（`/admin/settings.html#entry`），可**针对任意单个用户**关闭或开启其设置入口；区块内按「🛡️ 管理员 / 👥 普通用户」分类展示，仅显示当前管理员管理范围内的用户。区块顶部带筛选条：可按用户名 / 显示名关键词即时搜索，并按用户组、管理员/普通用户类别过滤（纯前端筛选，无需刷新）。
- 关闭后该用户顶栏不再显示「⚙️ 设置」，直接访问 `/settings.html` 也会被服务端拦截跳回首页；状态通过每次请求的会话自愈即时生效，无需重新登录。
- 该操作受独立的 **`manage_user_entry`（用户设置入口管理）** 权限控制，属于「用户管理」分类，可在权限矩阵中按组分配，也支持经二级授权单独授予某个管理员——被授权者即使没有 `manage_settings` 也可访问网站参数页使用该分区，但仍受管理范围约束（只能操作级别更低的用户或自管组同组成员）。
- 站点级的「顶部显示主题入口」总开关（网站参数设置）继续生效，用于控制设置页内主题皮肤区的整体显隐。

## 网站参数设置（manage_settings 权限）

后台 → 网站参数设置（`/admin/settings.html`），按分类组织，保存后即时应用（该权限可经权限矩阵/二级授权授予其他管理员）：

1. **基础信息**：站点名称、Logo（emoji 或图片 URL，带实时预览）。图片支持 png/jpg/gif/svg/webp/**ico** 等格式及 `data:image` 内嵌地址（含 `image/x-icon`）；需填写可被浏览器访问的 URL 或 data URI，不能填写本机文件路径（如 `C:\...`）。
2. **顶部导航**：内置按钮（后台管理 / 修改密码 / 退出）显隐；自定义顶部链接可增删改，每条链接可选择 **👀 访客可见（未登录也显示）或 🔒 仅登录可见**。
3. **底部版权**：页脚内容，支持纯文本 / HTML / Markdown，可放版权与备案链接。
4. **自定义代码**：全站自定义 CSS 与 JavaScript。
5. **登录与会话**：
   - **登录状态有效期**：可设置分钟 / 小时 / 天（存为秒），0 = 浏览器关闭即失效；会话 Cookie 与服务端空闲超时同步生效，过期跳转登录页提示重新登录。
   - **登录总开关（关闭所有人登录）**：勾选后除超级管理员外所有用户（含普通管理员）无法登录，已登录的非超管会话会被强制踢出；用于紧急维护。
   - **最大登录设备数 / 人**：限制每个账号同时在线的设备数量（0 = 不限制），超限的新登录被拒绝。
6. **界面显示开关**：
   - **首页当地天气**：搜索框下方展示天气条（温度/天气/湿度/风速/城市）。免 key 公开接口（Open-Meteo），优先浏览器精确定位，用户拒绝时按 IP 粗定位（ipapi.co），均失败则静默不显示；定位缓存 6 小时、天气缓存 10 分钟。
   - **用户列表「上次登录」列**：用户管理的管理员/普通用户两个页签均显示最近一次登录时间，悬停可看登录 IP（登录时自动记录于 users 表）。
7. **用户设置入口管理**：按「管理员 / 普通用户」分类列出管理范围内用户，逐人开关其「我的设置」入口（需 `manage_user_entry` 权限，可二级授权；与 1–6 类的 `manage_settings` 权限相互独立）。

## 权限分层（系统管理员 / 普通管理员）

- **系统管理员（⭐超级管理员组，级别 1）**：拥有全部权限；可在「用户组管理」中为普通管理员组分配**可管理用户组**，并可在「权限管理」中调整各组权限与用户级授权。
- **普通管理员（🛡️管理员组，级别 2）**：
  - 可在「管理员」页签查看系统管理员及同级管理员，但对其**只读**，不能做任何增删改；
  - 只能管理级别低于自己、且在超级管理员分配的用户组内的用户（列表、新增、改组、导入、管理自定义导航均受限）；
  - 未被分配可管理组时，「普通用户」列表为空；
  - 被授予 `can_delegate` 后可在「权限管理」中对低级别用户做二级授权。

> **用户列表分页**：用户管理页支持分页浏览，可通过底部分页栏把「每页显示个数」切换为 10 / 20 / 50 / 100 条；翻页与切换每页个数都会保留当前搜索关键词。

## 导航访问授权

- **按用户 / 用户组开放权限**：导航分组与导航项均提供「可见用户组」与「单独可见用户」勾选；均不勾选 = 对所有人公开，勾选后仅授权范围内可见。普通管理员只能在其可管理用户组范围内操作。
- **跳转方式**：点击导航项（`/jump/<id>.html`）只做有效性校验，随后直接 302 跳转到目标网址，门户不保存、不代理任何网站账号密码。

## 其他前台功能

- **搜索引擎**：搜索框内左侧下拉框切换引擎，即时生效；输入关键词后按引擎模板在新窗口打开结果。引擎由后台「🔍 搜索引擎管理」（`/admin/engines.html`）增删改查，权限 `manage_engines`（系统管理员默认拥有，也可授予普通管理员组）；URL 模板用 `%s` 表示关键词，图标支持 emoji/图片 URL，可停用。
- **用户自定义导航**：登录用户可在 `/mynav.html` 自助管理个人导航（卡片化预览、悬浮编辑/删除、弹窗编辑），首页「⭐ 我的导航」分区仅本人可见；持有 `manage_user_navs` 权限的管理员可在 `/admin/usernavs.html` 对范围内用户的自定义导航**增删改查**（弹窗编辑、逐用户添加面板），该权限同样可在权限矩阵分配或经二级授权授予。
- **URL 自动规范化**：自定义导航中不带协议的站内地址（如 `admin`）保存与渲染时自动补前导 `/`（→ `/admin`），保证在前台、后台任意页面点击都跳转到同一地址，不会出现 `/admin/admin`；外链请写完整 `https://` 地址。
- **搜索记录与关键词联想**：首页每次搜索都会记录关键词、引擎、IP 与时间（未登录访客同样记录）。输入时搜索框自动弹出联想——登录用户优先匹配<strong>本人历史搜索词</strong>，不足补全站热门词；访客使用全站热门；支持 ↑↓ 键选择、回车或鼠标点选，匹配片段高亮。持有 `view_search_logs` 权限的管理员可在 `/admin/searchlogs.html` 查看（本人及管理范围内记录），按关键词/用户/引擎筛选、分页浏览，顶部附热门词 Top 20；该权限可在权限矩阵分配或经二级授权授予，记录的单条/批量删除仅系统管理员可执行。

## 模块扩展

后台侧边栏由 `includes/modules.php` 中的 `$ADMIN_MODULES` 注册表统一渲染，按功能分为四个**可折叠二级菜单组**（门户导航、用户与权限、记录与日志、系统设置），「概览」为顶级链接；整组无可见模块时整组隐藏，含当前页面的组自动展开。后期新增模块只需：
1. 在 `$ADMIN_MODULES` 中注册一项（key / 名称 / URL / 所需权限 / 图标 / 所属菜单组 group）；
2. 在 `admin/` 下创建对应页面文件，页面中调用 `render_admin_sidebar('你的key')` 替代手写侧边栏。

前后台共用 `assets/style.css` 中的 CSS 变量（`--primary` 等）与组件类（`btn-primary`、`btn-mini`、`admin-form`、`data-table` 等）；全站输入框、下拉框、按钮采用统一控件度量（`--control-*`），主题天然统一。

## 后台概览数据

后台首页（`/admin/index.html`）采用与「用户管理」一致的**页签切换布局**（侧边栏 + 页签行 + 内容面板，点击页签即时切换显示，默认显示「数据总览」），四个页签分别为数据总览、用户组人数、用户最近登录、导航点击次数（页签带数量徽标）：

- **数据总览**：导航项数、导航总点击、用户组数、用户数四张统计卡片。
- **各用户组人数**：每个用户组（含超管/管理员标记）的当前用户数（按多组关联表统计，同一用户在多个组各计一次），另列「无分组」用户数。
- **导航点击次数**：每个导航项的累计点击量，按所属分组展示；点击在跳转入口 `jump.php` 中以原子自增记录（`nav_items.click_count`），仅统计经门户 `/jump` 入口的点击，用户个人导航直链不计入。
- **用户最近登录**：每个用户最近一次登录的 IP（`users.last_login_ip`，兼容 IPv4/IPv6）与时间（`users.last_login_at`），在登录成功时写入；普通管理员仅能看到级别低于自己、且在其管理范围内的用户，系统管理员可查看全部。

以上字段均通过幂等迁移为旧库自动补齐，历史用户首次升级后显示「从未登录」，再次登录即有数据。

## 用户操作日志

后台 → 📝 用户日志（`/admin/logs.html`）：

- **记录内容**：全站用户的登录成功/失败与退出、用户自助修改密码、切换皮肤（含恢复跟随默认）、个人导航增删改、强制下线设备、设置入口开关，以及后台各模块的新增/修改/删除、重置密码、批量导入、权限矩阵与用户级授权保存、网站参数保存等；每条含操作人（**显示名（用户名）**）、模块、详情、**操作 IP** 与**成功/失败状态**（登录失败、维护期拒绝登录同样记录）。**操作类型一律以中文显示**（无英文 action 直出），筛选下拉按「登录与账号 / 内容与导航 / 参数与权限」三组分类。
- **显示名快照**：每条日志在产生时固化操作人的显示名（`user_logs.display_name`），此后用户改名不影响历史记录；列表按「显示名（用户名）」展示，显示名为空时回退用户名。
- **非注册用户**：登录失败时若账号在系统中不存在，该条日志标注为「非注册用户」；已注册用户密码错误仍显示其本人显示名。旧库中「用户不存在的登录失败」记录在迁移时自动补标。
- **授权方式**：受独立的 **`view_logs`（查看用户日志）** 权限控制——系统管理员默认拥有；普通管理员/用户需由系统管理员在权限矩阵中授予用户组，或经二级授权授予单个用户。无权限者看不到侧边栏入口，直接输入 URL 同样被拦。
- **可见范围（服务端强制）**：系统管理员可查看全部日志；普通授权人仅可查看本人的日志，以及级别低于自己、且在其可管理组范围内用户的日志；已删除用户的历史日志仅系统管理员可见。
- 支持按操作类型、成功/失败状态筛选，按显示名/用户名或详情关键词搜索，并可自定义每页显示条数（20/50/100/200）。
- **日志删除**：仅系统管理员可执行，支持行内「删除」单条删除与勾选后「批量删除」（仅当前页）；删除前有确认提示，删除操作本身会留下一条审计日志，删除后跳回原筛选/分页视图。普通 `view_logs` 持有人看不到删除入口，直接构造请求同样被服务端拒绝。

## 安全说明

- 密码以 **MD5** 哈希保存（`md5($password)`）。注意：MD5 已不推荐用于存储密码，安全性弱于 bcrypt/argon2，如非历史系统兼容需要，建议改用更安全算法。
- 所有 SQL 均使用 PDO 预处理语句，防 SQL 注入。
- 所有输出经 `htmlspecialchars` 转义，防 XSS。
- 后台入口均有 `require_admin()` 鉴权。
- 批量导入已做用户名去重与用户组名校验。
